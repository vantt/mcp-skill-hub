## Confirmed findings

### HIGH-1: Codex TOML updater writes invalid config.toml when skillhub is declared by inline table or dotted key
- File: internal/hostintegration/toml_update.go:26-44 (section discovery) and :52-69 (append path)
- The updater only recognizes a `[mcp_servers.skillhub]` header and top-level dotted keys with the prefix `mcp_servers.skillhub.`. It misses these valid Codex forms:
  - `[mcp_servers]` followed by `skillhub = { command = "..." }`
  - top-level `mcp_servers.skillhub = { ... }` (exact match, with no trailing dot)
  - `[mcp_servers]` followed by `skillhub.command = "..."`
- In all three cases it appends a new `[mcp_servers.skillhub]` table. Python `tomllib` rejects the result: `Cannot declare ('mcp_servers', 'skillhub') twice`.
- Failure scenario: `skillhub doctor --fix --yes` atomically replaces a valid `.codex/config.toml` with an unparseable one. Codex then fails to load the whole config, including every other MCP server. `apply()` recomputes the same bytes, so the preimage/expected check passes, and nothing parses the output.
- Suggested fix: inside `[mcp_servers]`, treat an assignment whose normalized name is `skillhub` or starts with `skillhub.` as a conflict. At top level, treat `mcp_servers.skillhub` itself as a conflict too. Better still, parse the generated bytes with a real TOML decoder before returning (for example `github.com/pelletier/go-toml/v2`) and assert that the decoded `mcp_servers.skillhub` equals the managed values. Add these three cases to the tests.

### MEDIUM-1: JSON MCP updater silently deletes user keys inside the skillhub registration, and the preview hides it
- Files: internal/hostintegration/json_update.go:58-62 (the whole value is spliced), integration.go desiredClaudeConfig/desiredGeminiConfig, preview.go mcpChangePreview
- Probe input `{"mcpServers":{"skillhub":{..., "env":{"SKILLHUB_TOKEN":"x"}, "timeout":60000}}}` produces `{"mcpServers":{"skillhub":{"type":"stdio","command":...,"args":[...]}}}`. `env` and `timeout` are gone.
- The preview is headed "managed MCP fields only:" and lists only type, command and args, so the user approves without seeing that the deletion will happen.
- This is inconsistent with the Codex path, which keeps unmanaged keys in the table (the `custom_timeout = 99` preservation test). The JSON test only checks sibling servers, not keys inside `skillhub`.
- Failure scenario: a Claude or Gemini user who added `env`, `timeout`, `includeTools` or `headers` to the skillhub entry loses them on `doctor --fix`.
- Suggested fix: upsert each managed field with `upsertJSONPath(raw, ["mcpServers","skillhub",field], value)` so the other keys survive. Alternatively, report extra keys as a conflict, or list them as removed in the preview. Add a test with `env` inside the skillhub entry.

### MEDIUM-2: README documents a telemetry subcommand that does not exist
- File: README.md:89 `go run ./cmd/skillhub telemetry status --workspace ...`
- Running it returns exit 2 with `WHY: unsupported telemetry subcommand "status"`. The supported subcommands (internal/delivery/cli/telemetry.go:47-83) are `health`, `preview`, `export` and `purge`.
- Fix: change it to `telemetry health`.

### LOW-1: Misleading conflict reason when mcpServers is not an object
- File: internal/hostintegration/json_update.go:47. The message is built with `path[:len(path)-1]` on the recursive tail, so `{"mcpServers": null}` reports `JSON path "" is not an object`. `doctor` shows this string as the conflict reason.
- Fix: pass the full path prefix into the recursion, or build the message from the key being descended into.

## Checked and rejected (no action)
- **Symlinked workspace ancestors rejected:** this is existing workspace-package policy (`unsafe directory path`, reproduced), not introduced here.
- **install.sh security:** it requires curl, uses `--fail --proto =https --max-filesize`, and runs mktemp under TMPDIR with cleanup. The Sigstore identity is pinned to `release.yml@refs/tags/vX`, which matches the release workflow `CERTIFICATE_IDENTITY`. The archive must hold exactly one regular member. Checksum-line parsing handles `sha256sum`'s two-space format. No bypass was found outside the explicit `--local-fixture` test mode.
- **Workflows:** all actions are SHA-pinned and verified. Permissions are least-privilege per job. Untrusted inputs reach shell only through env. The checksum manifest covers every asset including install.sh and is signed before publish.
- **Atomic write:** host config writes use os.Root, an O_EXCL temp file, fsync, rename and a directory sync. The preimage digest is rechecked right before the write. Existing permission bits are preserved.
- **Doctor fix path:** apply and plan refuse on conflict.

## Unresolved questions
1. GitHub may rename release asset filenames that contain `+` (SemVer build metadata such as `v1.2.3+build.5`). In that case the installer's URL `skillhub-1.2.3+build.5-...tar.gz` would 404. This is unverified here and worth one dry-run tag before advertising build-metadata versions.
2. Users with cosign v3 locally: the release signs with cosign-installer v3.9.1 (cosign v2, legacy `--bundle` format). Confirm that `cosign verify-blob --bundle` in v3 still accepts that bundle format.
