# Phase 3: Compact advertised resolver request schema

## Gate

Open: the user chose option (a) on 2026-10-14.

User decision on plan open question 1. Today the advertised `skill_resolve` input schema is the committed contract
byte for byte and `server_test.go:195-203` enforces that. This phase changes that rule, so it does not start without an
explicit "yes" (option a) or "only `$id`/`$schema`" (option c, steps 2 and 4 only, no projection of bounds).

## Goal

Advertise a projection of `schemas/skill-resolve-request-v1.schema.json` that keeps everything that tells the model
what to send (types, properties, `required`, `enum`, `additionalProperties`, `$defs`/`$ref`, property descriptions)
and drops what only the validator needs (`$id`, `$schema`, `maxLength`, `minLength`, `maxItems`, `uniqueItems`,
`format`). The server validates every call against the full committed schema, so no bound is lost. The committed
schema file does not change.

Saving: 778 model-visible bytes (~195 tokens) per loaded `skill_resolve` in Claude Code (3,822 → 3,044 input schema
bytes). Zero in Codex, which already strips these keywords. The same projection applies to `routing_evaluate`
(curation) because both use `withCommittedResolverSchemas()`; that is free and keeps one code path.

## Files

- Modify: `internal/delivery/mcpserver/schema_shaping.go` — add `advertisedRequestSchema(committed)` (clone, drop the
  keywords above with `walkSchema`, which already visits properties, `$defs`, `anyOf` and `items`; also visit
  `prefixItems`/`oneOf` if the committed schema ever uses them) and use it in the `committedResolver` branch of
  `deriveToolSchemas` (line ~193). Add a `sync.OnceValues` that resolves the full committed request schema once

  `req.Params.Arguments` (decoded to `map[string]any`) against the resolved committed schema before
  `NormalizeRequest`. On failure return the same tool-error shape the SDK produces today
  (`validating "arguments": <detail>`, `IsError: true`). Do the same in the `routing_evaluate` handler
  (`insight_tools.go`), or through one shared helper.
- Modify: `internal/delivery/mcpserver/insight_tools.go` (validation call only).
- Modify: `internal/delivery/mcpserver/server_test.go` — replace the equality assertion at lines 195-203 with: the
  advertised schema equals `advertisedRequestSchema(committed)`, and contains every property, `required` list and

- Create: `internal/delivery/mcpserver/resolver_request_validation_test.go` — table test over the committed bounds:
  for each `maxLength`, `minLength`, `maxItems`, `uniqueItems` and `format` path in the committed schema (generated by

- Modify: `internal/delivery/mcpserver/tools_list_digest_test.go`, `tools_size_test.go` (re-pin, lower budgets).

## Steps

1. Write `resolver_request_validation_test.go` first and run it against the current code: it must pass today (the
   SDK enforces the full schema). This proves the test detects each bound.
2. Add the projection and the explicit validation in one commit; run the new test again (must still pass) and the
   updated `server_test.go` assertion.
3. Check `error_characterization_test.go` and `hardening_test.go` for pinned invalid-argument wording; keep the
   wording identical rather than editing those tests.
4. Re-pin digests (runtime, curation, all) and lower the budgets.
5. Run the routing eval on a temp workspace copy before and after; metrics must be identical.
6. Manual smoke as in phase 2 (one Claude Code, one Codex session): the agent still sends a valid request.

## Risks

- A bound slips through because the explicit validation is missing on some path (proxy, HTTP listener): all paths
  reach the same hub handler; the proxy forwards to the hub (`proxy.go`), which validates. The table test runs against
  the hub handler; add one case through `skillhub mcp proxy` in-memory if the proxy has its own argument decoding.
- Double validation cost: one extra schema validation per call on a ~4 KB schema, negligible next to resolution;
  confirm with `load_path_bench_test.go`.
- The projection drops a keyword that the model needs: only validator-only keywords are dropped; the subset test in
  `server_test.go` guards properties, `required` and `enum`.

## Rollback

Revert the commit(s). The committed schema file was never changed, so no consumer is affected.
