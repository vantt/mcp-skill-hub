## Requirements

1. `app.UsageService.Funnel(ctx, workspace, FunnelQuery{Since, Until time.Time; SkillID string}) (FunnelReport, error)`:
   - Window defaults to the last 30 days, clamped to 180 days; day granularity (UTC). `--since` accepts `Nd` or `YYYY-MM-DD`; `--until` accepts `YYYY-MM-DD`.
   - Reads rollups via `Recorder.Rollups`; reads the active skill IDs (excluding `system-curator`) from the current catalog generation.
   - **Overall:** resolution counts by status (`resolved`, `no_skill`, `needs_context`, `already_covered`, `failed`); recommended (primary, supporting); activations by attribution; acceptance rate = `activation:recommended / recommended:primary`; override count; miss count (`activation:after_no_skill`); unsolicited count; negative feedback after load; doctor runs and failure rate (`doctor:setup_required + unsupported_platform + failed` over all doctor runs); resolutions with `setup:setup_required`; transcript counts when present (`transcript:*`, `native:no_resolve` labeled "native skill use without a hub resolve").
   - **Per skill:** the same counters plus loads by resource kind.
   - **Lists:** `dead_skills` (active, zero recommendations and zero loads in the window), `recommended_never_activated` (recommended:primary > 0 and activation:recommended = 0), `negative_after_load` (skills with `feedback:negative_after_load > 0`).
   - Rates are `null` when the denominator is 0. The report states `window`, `raw_retention_days: 14`, `rollup_retention_days: 180`, and `basis` per metric (`server-observed`, `host-reported`, `transcript`).
2. CLI `skillhub telemetry funnel [--since <Nd|date>] [--until <date>] [--skill <id>] [--workspace <path>] [--json]`. Human output: an overall block, a per-skill table sorted by recommended desc (top 20, `--skill` shows one), then the three lists. Exit 0; unknown `--skill` → exit 2.
3. Web API `GET /api/v1/skills/{id}/usage?since=30d` → `FunnelReport` filtered to the skill (overall block omitted). Unknown skill → 404 via the existing `writeError` path. Read-only, same auth as other routes.
4. WebUI: a new **Usage** tab in Skill Detail (`?tab=usage`) rendering `UsagePanel`: window selector (7/30/90/180 days), counters (recommended, activated after recommendation, acceptance rate, overrides, misses, loads by kind, negative after load, doctor failures), and an empty state when all counts are zero. Uses existing design-system components and patterns from `ResourcesTab.tsx`; all strings in `en.ts`.

## Risks

| Risk | L × I | Mitigation |
|---|---|---|
| Users read host-reported and server-observed numbers as one | Medium × Medium | `basis` per metric in JSON and labels in human/UI output. |
| Opening a recorder per web request contends with the MCP writer | Low × Low | Read-only admin op; SQLite handles multi-process access; local UI traffic is light. |
| Day-granular windows surprise users comparing same-day changes | Low × Low | Documented; named cases deferred (D9). |
