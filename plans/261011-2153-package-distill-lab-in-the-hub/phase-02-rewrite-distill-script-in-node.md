# Phase 2: Rewrite the distill script as a self-contained Node module

## Context (traced)

  `list FILE [--top N=15] [--all]`, `decide FILE SELECTOR... --state {candidate,planned,ported,rejected}

  `<file>.yaml.tmp` and renames it over the file (`:320-331`).

## Requirements

1. **Vendoring.** Copy `package/dist/js-yaml.mjs` and `package/LICENSE` from `js-yaml-4.3.2.tgz` unmodified
   (keep the trailing `//# sourceMappingURL` line; Node ignores a missing map) as `vendor/js-yaml.mjs` and
   `vendor/js-yaml.LICENSE`. The test asserts both sha256 values above. Record version, source URL
   (`https://registry.npmjs.org/js-yaml/-/js-yaml-4.3.2.tgz`) and digests in a comment at the top of
   `distill.mjs` (the vendored file itself stays untouched).
2. **One module.** `distill.mjs` is a single ES module importing only `node:` built-ins (`fs`, `path`,
   `child_process`, `process`) and `./vendor/js-yaml.mjs` by relative path resolved from `import.meta.url`. No
   npm, no bundler, no network, no `skillhub` binary, no MCP. Use only APIs present in Node 18.0 (check each
   API's "Added in" line in the Node docs); Phase 8 runs it under an official Node 18 binary.
3. **Same surface.** Same subcommands, positional arguments, options, defaults, output lines, error texts
   (`ERROR/WHY/FIX`) and exit codes (1 for validation and lookup errors, 2 for usage errors), with a hand-written
   argument parser and `--help` text equal in content to the Python docstring plus the new `--hub` option.
4. **Hub location** (plan decision 12): `--hub <dir>` on `check` and `format`; else `$SKILLHUB_WORKSPACE`; else walk
   up from the current folder to the first folder containing `.skillhub/schema-version`. A given or env folder
   without the marker is an error. Resolve the hub only when the evidence check runs, so `--help`, `list`,
   `decide` and `--no-where` never need one. When it is needed and not found, exit 1 with
   `ERROR: no Skill Hub folder found` / `WHY: the evidence check reads source mirrors under
   <hub>/runtime/distill-lab/mirrors` / `FIX: run from inside the hub, set SKILLHUB_WORKSPACE, pass --hub <dir>,
   or add --no-where`. Never a stack trace: wrap `main` so unexpected errors print `ERROR:` and exit 1.
5. **Same behaviour**, rule by rule: validation messages, `impact_of`, `final_score`, sort order, `_drop_derived`,
   `check` warnings, `list` columns, `decide` selectors and `at`, evidence check with the same cache and line
   counting, re-parse and re-validate before writing, atomic write via `<file>.yaml.tmp` and rename.
6. **Load** with js-yaml `CORE_SCHEMA` so dates, hex SHAs and `yes`/`no` stay what the Python loader effectively
   produced for files this writer emits (strings for cursors and `at`). Keep a duplicate-key or syntax error as
   the existing `is not valid YAML` message.
7. **Writer parity with PyYAML** (plan decision 13). The writer emits the fixed layout itself and reproduces
   these PyYAML rules, each with a test input:
   - Python `round(x, 2)` on exact ties (half to even, e.g. `0.125 -> 0.12`, `0.375 -> 0.38`) and float text
     (`45.0`, `22.5`, `0.67`; integral floats keep `.0`; scores are ints);
   - plain vs single-quoted strings by PyYAML's YAML 1.1 implicit resolvers (bool `yes/no/on/off/true/false`
     in any case, null `~`/`null`, int including all-digit and `0x`/`0o`/`_` forms and all-digit 7 to 12 character
     SHAs, float including `1e5` forms and `.inf`, timestamps) and its scalar analysis (leading indicators,
     `: ` and ` #`, leading or trailing spaces, empty string), double quotes for non-printable characters,
     `allow_unicode` (no escaping of printable non-ASCII);
   - line wrapping of long plain and folded scalars at width 88 by PyYAML's emitter rule (break at a space once
     the column passes the width), indentation 2 with indented sequences, `>-` for folded prose without a final
     newline, flow `{state: x, reason: ..., at: ...}` and `[a, b, c]`, empty list `[]`;
   - blank line before each `  - key:` item; key orders as in Python; sort by key in code-point order;
   - Python `splitlines()` semantics for the evidence line count (`\r\n`, `\r`, `\v`, `\f`, `\x1c-\x1e`,
     `\x85`, ` `, ` `; no trailing empty line).
8. **Header.** Same four lines with the script name changed to `distill.mjs`:
   `# Written by distill-lab/scripts/distill.mjs. Edit freely, then run \`distill.mjs format\`.` The `distill.yaml`
   schema is unchanged; header lines are comments.
9. **Notices.** Extend `web/scripts/notices.mjs` with a short constant list of files vendored outside the web
   bundle (js-yaml 4.3.2, MIT, license read from `internal/systemskills/distill-lab/scripts/vendor/js-yaml.LICENSE`)
   appended as its own section, and widen the intro sentence to "the Web UI production bundle and files embedded
   in the skillhub binary". Regenerate with `cd web && npm run notices`.
10. **CI.** Add `SKILLHUB_REQUIRE_NODE: "1"` to the `verify` job env so a missing Node fails instead of skipping.

  `t.Skip("node not found on PATH; install Node 18 or newer to run the distill-lab script tests")`, unless
  `SKILLHUB_REQUIRE_NODE=1`, then `t.Fatal`. Run the mirrored `distill-lab/scripts/distill.mjs` in temp folders:
  - vendored file digests equal the values in requirement 1;
  - `--help` exit 0; usage error exit 2;
  - for each fixture in `internal/migration/testdata/*-distill.yaml` copied into a temp hub
    (`skills/default/<id>/.meta/distill.yaml` plus `.skillhub/schema-version`): `format --no-where` output equals
    the fixture byte for byte except the first header line, or equals the committed golden file under
    `testdata/distill/` if the fallback was taken; `distill.UnmarshalDocument` + `ValidateDocument` accept it;
    a second `format` is a no-op;
  - `list --top 5` and `list --all` output equal golden files;
  - `decide` by number and by key, `--state rejected` without `--reason` fails, `at` is the 12-character cursor;

    commit; valid, unresolved, range-too-long and reversed-range refs give the Python messages; files with

  - hub lookup: `--hub`, `$SKILLHUB_WORKSPACE`, walking up, none found (message, exit 1, no stack trace);
  - edge-case inputs from requirement 7 (one small input file per rule) equal golden outputs.

## Steps

1. Download `js-yaml-4.3.2.tgz` into a scratch folder (`npm pack js-yaml@4.3.2`), verify the two digests, copy
   the two files into `vendor/` in both trees.
2. Port constants, scoring, validation, evidence check and commands; then the writer.
3. Build edge-case inputs; run the differential comparison; fix until clean or until a difference is shown to be
   impossible to remove (then apply the fallback below).
4. Commit golden outputs and the Go test; notices; CI env line.
5. `go test ./internal/systemskills/...`, `make check`, `make web-check`.
6. Commits: `feat(distill-lab): rewrite the distill script as a self-contained Node module`,
   `chore(notices): list the js-yaml copy embedded in the binary`.

## Fallback if byte parity is impossible

If an input class cannot match PyYAML byte for byte (for example an exotic quoting case), keep the js-yaml-side
output for that class, commit it as the golden file, note the difference in a short "Format changes" line in
SKILL.md (Phase 3 copies it) and in the release-note line (Phase 7), and keep the Go reader tests passing. The two
existing fixtures must still round-trip unchanged apart from the header line; if even they cannot, stop and report
to the lead before reformatting them.

## Risks

- Hidden PyYAML behaviour not covered by an input: the differential run over both 42-lesson fixtures plus
  targeted inputs bounds it; owners' existing files are reformatted at worst once, by the documented fallback.
- Windows: `git` via `child_process.spawnSync` with an argument array (no shell), paths through `node:path`,
  `\r\n` input handled by the loader; CI runs the test on Windows.
- Vendored file drift: digests asserted by the test.

## Rollback

Revert the commits; the bundle then has no script and Phase 3/4 consumers are not yet merged in this wave.
